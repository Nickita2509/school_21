# 🍕 SQL1: Deep Diving into JOINs and CTEs (Day 02)

## 📌 О проекте
Углубленное изучение реляционной алгебры и продвинутых операций соединения (JOIN) в PostgreSQL. Проект охватывает работу с LEFT/RIGHT/FULL OUTER JOIN, обработку отсутствующих данных (COALESCE), использование обобщенных табличных выражений (CTE), функцию `generate_series` и самосоединение (Self-Join) для решения сложных аналитических задач на примере модели данных сети пиццерий.

## 📂 Структура проекта
Решения разбиты по директориям в соответствии с номерами заданий. В каждой папке находится один SQL-скрипт:
- 📁 **`src/ex00/`** → 📄 `day02_ex00.sql` (Поиск отсутствующих записей через OUTER JOIN без IN/EXISTS)

- 📁 **`src/ex02/`** → 📄 `day02_ex02.sql` (Полный охват данных через FULL JOIN и обработка NULL через COALESCE)
- 📁 **`src/ex03/`** → 📄 `day02_ex03.sql` (Рефакторинг запроса с использованием CTE)
- 📁 **`src/ex04/`** → 📄 `day02_ex04.sql` (Фильтрация меню по специфическим названиям пицц)
- 📁 **`src/ex05/`** → 📄 `day02_ex05.sql` (Демографическая фильтрация: женщины старше 25 лет)

## ⚙️ Детальное описание выполненных задач

- **Part 1. OUTER JOIN и поиск отсутствующих данных (Tasks 00, 02):**  
  Реализовал поиск пиццерий, которые не посещал ни один клиент, используя `LEFT JOIN` с последующей фильтрацией `NULL`-значений, строго соблюдая запрет на использование `IN`, `EXISTS` и операций над множествами. В задании 02 применил `FULL OUTER JOIN` для получения полного списка посетителей и пиццерий за период 1–3 января 2022 года, обработав отсутствующие значения функцией `COALESCE` (замена на '-').

- **Part 2. Генерация данных и CTE (Tasks 01, 03):**  
  Написал запрос для выявления пропущенных дат визитов (с 1 по 10 января 2022) с использованием системной функции `generate_series`. В задании 03 провел рефакторинг этого кода, инкапсулировав генерацию дат в Common Table Expression (CTE), что значительно улучшило читаемость и модульность запроса.

- **Part 3. Множественные соединения и фильтрация (Tasks 04–06):**  
  Составил серию запросов с `INNER JOIN` для связывания таблиц `person`, `person_order`, `menu` и `pizzeria`. Реализовал точечную фильтрацию по названиям пицц (грибы, пепперони), демографическим признакам (женщины > 25 лет) и конкретным именам клиентов (Денис, Анна) с корректной многоуровневой сортировкой.

- **Part 4. Сложная аналитика и условия (Tasks 07–08):**  
  Реализовал нетривиальную выборку: поиск пиццерии, которую посетил конкретный клиент (Дмитрий) в заданную дату, с дополнительным условием минимальной цены (< 800 руб). В задании 08 применил комбинацию условий `OR`/`AND` для поиска мужчин из Москвы или Самары, заказавших специфические виды пиццы.

- **Part 5. Логика пересечения и самосоединение (Tasks 09–10):**  
  Для поиска женщин, заказавших *обе* пиццы (сырную и пепперони), реализовал логику пересечения множеств через группировку или повторные JOIN. В задании 10 успешно применил Self-Join (самосоединение) таблицы `person` с корректным алиасингом столбцов (`person_name1`, `person_name2`, `common_address`) для выявления людей, проживающих в одном городе.

## 🚀 Как проверить

1. **Подготовка:** Убедись, что у тебя развернута СУБД PostgreSQL и применен исходный скрипт `model.sql` из папки `materials`.
2. **Запуск:** Перейди в директорию нужного задания (`src/exXX`).
3. **Выполнение:** Запусти файл `day02_exXX.sql` через терминал (`psql -d your_db -f day02_exXX.sql`) или через графический клиент (DataGrip / pgAdmin).
4. **Валидация:** Сверь структуру, наличие/отсутствие `NULL`-значений (и их замену через `COALESCE`), а также порядок строк в выводе с требованиями конкретного задания.
