# 🐍 Python Bootcamp: Web API, Clean Architecture & Minimax (Project 03)

## 📌 О проекте
Проект по созданию полноценного веб-приложения на Python с использованием фреймворка Flask. Ключевая особенность — строгое соблюдение принципов чистой архитектуры (Clean Architecture) с разделением на слои: Domain, Datasource, Web и Dependency Injection (DI). В качестве бизнес-логики реализована игра «Крестики-нолики» с непобедимым ИИ-оппонентом на базе алгоритма Минимакс (Minimax), поддержкой одновременных сессий и потокобезопасным хранением состояния.

## 📂 Структура проекта
Проект строго модулизирован. Каждый слой и его компоненты (модели, интерфейсы, реализации) вынесены в отдельные файлы в директории `src/`:
- 📁 **`src/domain/`** → Бизнес-логика: модели игрового поля (матрица) и сессии (UUID), интерфейсы сервисов, логика валидации ходов и алгоритм Минимакс.
- 📁 **`src/datasource/`** → Работа с данными: потокобезопасное in-memory хранилище, реализация паттерна Repository, мапперы Domain ↔ Datasource.
- 📁 **`src/web/`** → Транспортный слой: Flask-контроллеры, маршрутизация (`POST /game/{uuid}`), DTO-модели для API, мапперы Domain ↔ Web, обработка ошибок.
- 📁 **`src/di/`** → Внедрение зависимостей: класс `Container`, описывающий граф зависимостей (Singleton для хранилища, инъекция репозитория в сервис).
- 📄 **`src/main.py`** → Точка входа в приложение, инициализация DI-контейнера и запуск Flask-сервера.

## 🛠 Стек технологий и инструменты
- **Язык и фреймворк:** Python 3.x, Flask
- **Архитектурные паттерны:** Clean Architecture, Dependency Injection (DI), Repository Pattern, Mapper Pattern, DTO.
- **Алгоритмы и структуры данных:** Алгоритм Минимакс (Minimax) для ИИ, целочисленные матрицы, UUID.
- **Конкурентность:** Потокобезопасные коллекции (`threading.Lock` / `threading.RLock`) для корректной работы с состоянием при одновременных запросах.
- **Инструменты:** `venv`, Postman / `curl` (для тестирования API).

## ⚙️ Детальное описание выполненных задач

- **Part 1. Архитектурное проектирование и DI (Tasks 1, 5):**  
  Спроектировал модульную структуру приложения, строго разделив ответственность между слоями. Реализовал слой DI (`Container`), который управляет жизненным циклом объектов: хранилище зарегистрировано как Singleton, репозиторий и сервис получают зависимости через конструктор (Constructor Injection), что обеспечивает слабую связность и легкость тестирования.

- **Part 2. Доменная логика и ИИ (Task 2):**  
  Реализовал ядро приложения в слое Domain. Игровое поле представлено целочисленной матрицей. Разработал сервис, который включает строгую валидацию игрового поля (защита от изменения предыдущих ходов), проверку условий победы/ничьей и генерацию оптимального ответного хода компьютера с использованием рекурсивного **алгоритма Минимакс**.

- **Part 3. Потокобезопасное хранение данных (Task 3):**  
  В слое Datasource реализовал паттерн Repository для абстрагирования логики хранения. Для поддержки множества одновременных игр использовал потокобезопасные структуры данных (с применением механизмов синхронизации), гарантируя отсутствие состояний гонки (race conditions) при параллельных HTTP-запросах. Написал мапперы для преобразования Domain-моделей в формат хранения и обратно.

- **Part 4. RESTful API и обработка ошибок (Task 4):**  
  Разработал Web-слой на базе Flask. Реализовал эндпоинт `POST /game/{uuid}`, который принимает состояние поля от пользователя, валидирует его, передает в Domain-сервис для получения хода ИИ и возвращает обновленное состояние игры. Предусмотрена детальная обработка ошибок: при передаче некорректного UUID или недопустимого хода API возвращает осмысленный ответ с кодом `400 Bad Request`.
