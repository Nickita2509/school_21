# 🍕 SQL1: Advanced JOINs and Data Manipulation (DML) (Day 03)

## 📌 О проекте
Углубленная работа с реляционными соединениями, операциями над множествами и языком манипулирования данными (DML: `INSERT`, `UPDATE`, `DELETE`). Проект включает решение аналитических задач с использованием Self-Join, динамическую генерацию идентификаторов через подзапросы, массовую вставку данных (`INSERT ... SELECT` с `generate_series`) и обеспечение целостности данных при их модификации.

## 📂 Структура проекта
Решения разбиты по директориям в соответствии с номерами заданий. В каждой папке находится один SQL-скрипт:

## ⚙️ Детальное описание выполненных задач

- **Part 1. Сложная фильтрация и Anti-Join (Tasks 00-02):**  
  Реализовал многоуровневую выборку данных для конкретного клиента с ценовыми ограничениями. В задании 01 успешно нашел невостребованные позиции меню, строго соблюдая запрет на использование `JOIN` (применив логику `EXCEPT` или подзапросы), а в задании 02 расширил этот вывод, добавив связанные данные через `INNER JOIN`.

- **Part 2. Операции над множествами (Tasks 03-05):**  
  Применил `EXCEPT` и `INTERSECT` для сравнения паттернов поведения клиентов. Реализовал логику поиска пиццерий, которые посещали исключительно мужчины или исключительно женщины, а также выявил случаи, когда клиент посетил заведение, но не совершил заказ (классический Anti-Join сценарий).

- **Part 3. Самосоединение (Self-Join) (Task 06):**  
  Написал запрос с алиасингом одной и той же таблицы (`menu`) для поиска дубликатов названий пицц с идентичной ценой, но принадлежащих разным пиццериям, исключив зеркальные дубликаты в выдаче.

- **Part 4. Динамическое управление данными (Tasks 07-10):**  
  Перешел от жестко заданных значений к динамическим `INSERT`. Реализовал добавление новых пицц, визитов и заказов, используя подзапросы для автоматического расчета следующего доступного `ID` (`MAX(id) + 1`) и поиска внешних ключей по названиям (`pizzeria_id`, `person_id`, `menu_id`). Это гарантирует целостность данных и защищает от ошибок при изменении исходной таблицы.

- **Part 5. Массовые операции и очистка (Tasks 11-13):**  
  Применил `UPDATE` с математическим выражением для изменения цены. В задании 12 реализовал эффективную массовую вставку заказов для всех клиентов с использованием конструкции `INSERT INTO ... SELECT ...` в связке с функцией `generate_series`. В финальном задании 13 выполнил безопасную очистку базы, удалив созданные тестовые заказы и позиции меню через целевые `DELETE` запросы.

## 🚀 Как проверить

1. **Подготовка:** Убедись, что у тебя развернута СУБД PostgreSQL и применен исходный скрипт `model.sql` из папки `materials`.
2. **Последовательность:** Задания 07–13 являются **DML-операциями**, изменяющими состояние базы. Их необходимо запускать строго по порядку.
3. **Выполнение:** Перейди в директорию `src/exXX` и запусти файл `day03_exXX.sql` через терминал (`psql -d your_db -f day03_exXX.sql`) или графический клиент.
4. **Валидация:** Для заданий 00–06 сверь вывод с ожидаемым результатом. Для заданий 07–13 проверь количество затронутых строк (`INSERT X rows`, `UPDATE 1 row`, `DELETE Y rows`) и корректность изменения данных через `SELECT`.
