# 🍕 SQL1: Views, Materialized Views, and Set Operations (Day 04)

## 📌 О проекте
Углубленная работа с абстракциями баз данных: создание и управление виртуальными таблицами (Views) и материализованными представлениями (Materialized Views). Проект охватывает генерацию временных диапазонов, применение операций теории множеств (симметрическая разность), расчетные вычисления внутри представлений и полный жизненный цикл управления объектами схемы (создание, обновление, удаление).

## 📂 Структура проекта
Решения разбиты по директориям в соответствии с номерами заданий. В каждой папке находится один SQL-скрипт:
- 📁 **`src/ex00/`** → 📄 `day04_ex00.sql` (Создание представлений с фильтрацией по полу)
- 📁 **`src/ex01/`** → 📄 `day04_ex01.sql` (Объединение данных из двух представлений через UNION)
- 📁 **`src/ex02/`** → 📄 `day04_ex02.sql` (Генерация календарного диапазона через view и `generate_series`)
- 📁 **`src/ex03/`** → 📄 `day04_ex03.sql` (Поиск пропущенных дат визитов с использованием EXCEPT)
- 📁 **`src/ex04/`** → 📄 `day04_ex04.sql` (Реализация симметрической разности множеств: (R − S) ∪ (S − R))
- 📁 **`src/ex05/`** → 📄 `day04_ex05.sql` (Расчетное представление с функцией `round` для скидки)
- 📁 **`src/ex06/`** → 📄 `day04_ex06.sql` (Создание материализованного представления для кэширования сложного запроса)
- 📁 **`src/ex07/`** → 📄 `day04_ex07.sql` (Динамическая вставка данных и обновление состояния материализованного представления)
- 📁 **`src/ex08/`** → 📄 `day04_ex08.sql` (Очистка схемы базы данных: удаление всех созданных представлений)

## 🛠 Стек технологий и инструменты
- **СУБД:** PostgreSQL
- **Язык запросов:** ANSI SQL (DDL для представлений, DML для данных)
- **Инструменты:** psql, DataGrip / pgAdmin
- **Концепции:** `CREATE VIEW`, `CREATE MATERIALIZED VIEW`, `REFRESH MATERIALIZED VIEW`, `DROP VIEW`, `generate_series`, операции над множествами (`UNION`, `EXCEPT`), функция `round()`.

## ⚙️ Детальное описание выполненных задач

- **Part 1. Создание и композиция представлений (Tasks 00-01, 05):**  
  Реализовал абстракцию данных, создав отдельные представления для фильтрации клиентов по полу (`v_persons_female`, `v_persons_male`). Объединил их результаты с помощью `UNION` для получения единого отсортированного списка. В задании 05 создал сложное представление `v_price_with_discount`, которое на лету рассчитывает стоимость со скидкой 10% и корректно округляет результат функцией `round()`.

- **Part 2. Генерация данных и анализ пропусков (Tasks 02-03):**  
  Использовал системную функцию `generate_series` для создания эталонного представления календарных дат (`v_generated_dates`). Применил операцию `EXCEPT` для сравнения эталонного диапазона с фактическими датами визитов, что позволило эффективно выявить и отсортировать пропущенные дни.

- **Part 3. Теория множеств в SQL (Task 04):**  
  Реализовал нетривиальную логику симметрической разности множеств по формуле $(R - S) \cup (S - R)$. Написал запрос, находящий клиентов, которые посетили пиццерию либо 2-го, либо 6-го января, но не в оба дня одновременно, и инкапсулировал эту логику в представление `v_symmetric_union`.

- **Part 4. Материализованные представления и их жизненный цикл (Tasks 06-08):**  
  Создал материализованное представление `mv_dmitriy_visits_and_eats` для кэширования результатов аналитического запроса. Смоделировал изменение данных в реальной системе: динамически (без жестко заданных ID) добавил новый валидный визит клиента, после чего выполнил команду `REFRESH MATERIALIZED VIEW` для актуализации кэша. В финальном задании 08 провел корректную очистку схемы базы данных, удалив все созданные виртуальные и материализованные объекты через `DROP VIEW`.

## 🚀 Как проверить

1. **Подготовка:** Убедись, что у тебя развернута СУБД PostgreSQL, применен скрипт `model.sql`, и сохранены все изменения из предыдущего дня (Day 03, DML).
2. **Последовательность:** Задания 06 и 07 являются зависимыми. Скрипт из `ex07` должен выполняться строго после `ex06`, так как он модифирует данные и обновляет состояние материализованного представления.
3. **Выполнение:** Перейди в директорию `src/exXX` и запусти файл `day04_exXX.sql` через терминал (`psql -d your_db -f day04_exXX.sql`) или графический клиент.
4. **Валидация:** Для заданий 00-05 проверь структуру и данные через `SELECT * FROM view_name`. Для заданий 06-07 убедись, что после `REFRESH` материализованное представление отображает обновленный набор строк. Задание 08 должно успешно удалить все объекты без ошибок.
