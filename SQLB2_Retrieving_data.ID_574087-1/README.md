# 🍕 SQL1: Sets, Subqueries and JOINs (Day 01)

## 📌 О проекте
Освоение операций над множествами (UNION, EXCEPT, INTERSECT) и различных типов соединений (JOIN, NATURAL JOIN) в PostgreSQL. Проект включает написание сложных аналитических запросов, работу с декартовым произведением, оптимизацию условий фильтрации (IN vs EXISTS) и строгое соблюдение архитектурных ограничений (запрет на использование определенных конструкций) на примере реляционной модели данных сети пиццерий.

## ⚙️ Детальное описание выполненных задач

- **Part 1. Объединение множеств (Tasks 00-01):**  
  Реализовал консолидацию разнородных данных из таблиц `person` и `menu` с помощью операторов `UNION` и `UNION ALL`. Настроил сложную сортировку, гарантирующую, что записи из таблицы людей всегда предшествуют записям меню, с сохранением дубликатов там, где это требовалось по условию.

- **Part 2. Альтернативная дедупликация (Task 02):**  
  Написал запрос для получения уникальных названий пицц, строго соблюдая запрет на использование `DISTINCT`, `GROUP BY`, `HAVING` и любых `JOIN`. Применил альтернативные подходы к фильтрации дубликатов, демонстрируя глубокое понимание работы движка СУБД.

- **Part 3. Пересечение множеств (Tasks 03, 06):**  
  Вычислил пересечение (`INTERSECT`) дат посещений и дат заказов для выявления клиентов, которые в один и тот же день и были в заведении, и оформляли заказ. В задании 06 усложнил логику, заменив ID на имена через неявное соединение и применив многоуровневую сортировку (по дате возрастания, по имени убывания).

- **Part 4. Разность множеств (Task 04):**  
  Реализовал операцию `EXCEPT ALL` для поиска ID посетителей, которые не делали заказы в конкретную дату (7 января 2022), с обязательным сохранением кратности (дубликатов) в итоговой выборке.

- **Part 5. Декартово произведение (Task 05):**  
  Сгенерировал полное декартово произведение (Cartesian Product) таблиц `person` и `pizzeria` для получения всех возможных теоретических комбинаций записей, что полезно для стресс-тестирования логики связей.

- **Part 6. Эволюция JOIN (Tasks 07-08):**  
  Применил явные `JOIN` для связывания данных о заказах и клиентах с конкатенацией и форматированием строки вывода. В задании 08 успешно мигрировал этот же запрос на использование `NATURAL JOIN`, строго соблюдая архитектурное ограничение на полный запрет других видов `JOIN`.

- **Part 7. Оптимизация условий (Task 09):**  
  Составил два семантически идентичных запроса для поиска пиццерий, которые не посещали клиенты. Реализовал логику через оператор `IN` и через коррелированный подзапрос с `EXISTS`, демонстрируя понимание различий в их выполнении и областях применения.

- **Part 8. Глобальное соединение (Task 10):**  
  Построил комплексный запрос с множественными `JOIN` для связывания трех таблиц (`person`, `menu`, `pizzeria`). Сформировал итоговый отчет, отсортированный по трем столбцам одновременно (имя клиента, название пиццы, название пиццерии).

## 🚀 Как проверить

1. **Подготовка:** Убедись, что у тебя развернута СУБД PostgreSQL и применен исходный скрипт `model.sql` из папки `materials`.
2. **Запуск:** Перейди в директорию нужного задания (`src/exXX`).
3. **Выполнение:** Запусти файл `day01_exXX.sql` через терминал (`psql -d your_db -f day01_exXX.sql`) или через графический клиент (DataGrip / pgAdmin).
4. **Валидация:** Сверь структуру, наличие/отсутствие дубликатов и порядок строк в выводе с требованиями конкретного задания (особенно внимание к сортировке и запрету определенных конструкций).
