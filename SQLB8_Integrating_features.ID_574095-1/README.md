# 🍕 SQL1: Schema Design, Constraints, and Sequences (Day 06)

## 📌 О проекте
Реализация бизнес-логики на уровне базы данных через проектирование схемы, обеспечение целостности данных и автоматизацию рутинных операций. Проект охватывает создание таблиц с именованными ограничениями (Constraints), массовую вставку данных с агрегацией (`INSERT ... SELECT`), применение уникальных индексов, добавление метаданных (Comments) и настройку последовательностей (Sequences) для автоматической генерации первичных ключей.

## 📂 Структура проекта
Решения разбиты по директориям в соответствии с номерами заданий. В каждой папке находится один SQL-скрипт:
- 📁 **`src/ex00/`** → 📄 `day06_ex00.sql` (Создание таблицы `person_discounts` с PK, FK и типом `numeric`)
- 📁 **`src/ex01/`** → 📄 `day06_ex01.sql` (Массовое заполнение таблицы через `INSERT ... SELECT` с `ROW_NUMBER()` и условной логикой)
- 📁 **`src/ex02/`** → 📄 `day06_ex02.sql` (Аналитический запрос: расчет истории заказов с применением персональных скидок)
- 📁 **`src/ex03/`** → 📄 `day06_ex03.sql` (Создание уникального многоколоночного индекса и доказательство через `EXPLAIN ANALYZE`)
- 📁 **`src/ex04/`** → 📄 `day06_ex04.sql` (Добавление строгих ограничений целостности: `NOT NULL`, `CHECK`, `DEFAULT`)
- 📁 **`src/ex05/`** → 📄 `day06_ex05.sql` (Документирование схемы: добавление `COMMENT ON` для таблицы и столбцов)
- 📁 **`src/ex06/`** → 📄 `day06_ex06.sql` (Автоматизация PK: создание Sequence и динамическая инициализация значения)

## ⚙️ Детальное описание выполненных задач

- **Part 1. Проектирование схемы и миграция данных (Tasks 00-01):**  
  Спроектировал и создал таблицу `person_discounts` с явным именованием ограничений внешних ключей (шаблон `fk_{table}_{column}`). Реализовал массовое заполнение таблицы на основе истории заказов, используя `GROUP BY` для агрегации и условную логику для расчета скидки (10.5%, 22%, 30%). Для генерации первичного ключа успешно применил оконную функцию `ROW_NUMBER() OVER ()`.

- **Part 2. Аналитика и оптимизация доступа (Tasks 02-03):**  
  Написал сложный `JOIN`-запрос для отображения истории заказов с динамическим расчетом итоговой цены с учетом персональной скидки. Для предотвращения дублирования пар "клиент-пиццерия" создал уникальный многоколоночный индекс `idx_person_discounts_unique` и подтвердил его использование планировщиком через `EXPLAIN ANALYZE`.

- **Part 3. Обеспечение целостности и документирование (Tasks 04-05):**  
  Усилил надежность схемы, добавив именованные ограничения `NOT NULL` (`ch_nn_...`) и `CHECK` (`ch_range_discount` для диапазона 0–100%), а также установил значение `DEFAULT 0` для столбца скидки. В соответствии с практиками Data Governance, добавил содержательные комментарии (`COMMENT ON`) к таблице и каждому её атрибуту на русском/английском языке.

- **Part 4. Автоматизация генерации ключей (Task 06):**  
  Заменил ручное или оконное назначение ID на автоматизированное. Создал объект Sequence (`seq_person_discounts`), назначил его как `DEFAULT` для столбца `id` и программно инициализировал текущее значение последовательности на основе формулы `COUNT(*) + 1`, что гарантированно предотвращает конфликты нарушения первичного ключа (PK violation) при будущих вставках.

## 🚀 Как проверить

1. **Подготовка:** Убедись, что развернута СУБД PostgreSQL, применен `model.sql`, и сохранены все изменения из предыдущих дней (Day 03–05).
2. **Последовательность:** Задания являются инкрементными. Скрипты должны выполняться строго по порядку (от `ex00` к `ex06`), так как каждое последующее опирается на структуру или данные, созданные ранее.
3. **Выполнение:** Перейди в директорию `src/exXX` и запусти файл `day06_exXX.sql` через терминал (`psql -d your_db -f day0 my_db.sql`) или графический клиент.
4. **Валидация:** 
   - Для Task 03 проверь вывод `EXPLAIN ANALYZE` на наличие `Index Scan`.
   - Для Task 04 проверь структуру таблицы через `\d person_discounts` в psql, чтобы убедиться в наличии всех `CHECK` и `NOT NULL` ограничений.
   - Для Task 05 проверь комментарии через `\d+ person_discounts`.
