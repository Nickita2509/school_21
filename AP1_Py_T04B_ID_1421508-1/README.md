# 🐍 Python Bootcamp: Persistence, Auth & Multiplayer (Project 04)

## 📌 О проекте
Эволюция веб-приложения «Крестики-нолики» с добавлением персистентного хранения данных, системы безопасности и мультиплеерной логики. Проект демонстрирует переход от in-memory хранилища к полноценной реляционной СУБД (PostgreSQL) через ORM SQLAlchemy, реализацию HTTP Basic Authentication с защитой эндпоинтов через middleware-паттерн, а также внедрение State Machine для управления жизненным циклом multiplayer-сессий.

## 📂 Структура проекта
Проект расширяет архитектуру из Project 03, добавляя новые компоненты в соответствующие слои:
- 📁 **`src/domain/`** → Бизнес-логика: модели пользователей (User), состояния игры (GameState enum), улучшенная логика определения победителя с учетом состояний.
- 📁 **`src/datasource/`** → Персистентность: SQLAlchemy-модели с аннотациями, репозитории для работы с PostgreSQL, миграции схемы БД.
- 📁 **`src/web/`** → Транспортный слой: новые контроллеры (AuthController, GameLobbyController), DTO для регистрации/авторизации, middleware `UserAuthenticator` для защиты эндпоинтов.
- 📁 **`src/di/`** → Внедрение зависимостей: обновленный `Container` с регистрацией SQLAlchemy-сессий, сервисов авторизации и репозиториев.
- 📄 **`src/main.py`** → Точка входа: инициализация БД, регистрация middleware, запуск Flask-сервера.

## ⚙️ Детальное описание выполненных задач

- **Part 1. Персистентное хранение данных (Task 01):**  
  Заменил потокобезопасное in-memory хранилище на полноценную реляционную базу данных PostgreSQL. Интегрировал SQLAlchemy ORM, описав модели сущностей (Game, User, Board) с использованием декларативных аннотаций. Реализовал паттерн Repository для абстрагирования работы с БД, обеспечив прозрачную замену источника данных без изменения бизнес-логики.

- **Part 2. Система авторизации и защиты API (Task 02):**  
  Спроектировал и реализовал полноценную систему AAA (Authentication, Authorization, Accounting):
  - **Регистрация:** эндпоинт `POST /auth/signup` принимает `SignUpRequest` (логин + пароль), хеширует пароль и сохраняет пользователя в БД.
  - **Аутентификация:** эндпоинт `POST /auth/login` принимает заголовок `Authorization: Basic base64(login:password)`, валидирует учетные данные и возвращает UUID пользователя.
  - **Защита эндпоинтов:** реализовал middleware-структуру `UserAuthenticator`, которая перехватывает входящие запросы, извлекает и валидирует заголовок `Authorization`. При отсутствии или невалидности credentials возвращает `401 Unauthorized`. Эндпоинты `/auth/*` исключены из проверки.

- **Part 3. Мультиплеерная логика и State Machine (Task 03):**  
  Расширил доменную модель игры, добавив состояния (WaitingForPlayers, PlayerTurn, Draw, Victory) и информацию о символах игроков (X/O). Реализовал State Machine для управления переходами между состояниями:
  - **Создание игры:** `POST /game/create` — создание новой сессии (PvP или PvE).
  - **Лобби:** `GET /games` — получение списка доступных игр в состоянии `WaitingForPlayers`.
  - **Присоединение:** `POST /game/{uuid}/join` — второй игрок входит в игру, состояние меняется на `PlayerTurn`.
  - **Ход:** `POST /game/{uuid}` — обновленный эндпоинт, проверяющий, чей сейчас ход, и валидирующий ход текущего игрока.
  - **Просмотр:** `GET /game/{uuid}` — получение текущего состояния игры.
  - **Профиль:** `GET /user/{uuid}` — получение информации о пользователе.
