# 🍕 SQL1: Relational Data Model and Basic Queries (Day 00)

## 📌 О проекте
Комплексная отработка навыков написания SQL-запросов на диалекте ANSI SQL в СУБД PostgreSQL. Проект охватывает фильтрацию данных, работу с подзапросами (в частях `SELECT` и `FROM`), использование условной логики (`CASE`), конкатенацию строк и строгую сортировку результатов на примере реляционной модели данных сети пиццерий.

## 📂 Структура проекта
Решения разбиты по директориям в соответствии с номерами заданий. В каждой папке находится один SQL-скрипт:
- 📁 **`src/ex00/`** → 📄 `day00_ex00.sql` (Базовая фильтрация и сортировка)
- 📁 **`src/ex01/`** → 📄 `day00_ex01.sql` (Множественные условия `WHERE`)
- 📁 **`src/ex02/`** → 📄 `day00_ex02.sql` (Диапазоны: операторы сравнения vs `BETWEEN`)
- 📁 **`src/ex03/`** → 📄 `day00_ex03.sql` (Уникальные значения `DISTINCT` и логика `OR`)
- 📁 **`src/ex04/`** → 📄 `day00_ex04.sql` (Конкатенация строк и форматирование вывода)
- 📁 **`src/ex05/`** → 📄 `day00_ex05.sql` (Скалярные подзапросы в `SELECT` без `JOIN`/`IN`)
- 📁 **`src/ex06/`** → 📄 `day00_ex06.sql` (Вычисляемые булевы поля в подзапросах)
- 📁 **`src/ex07/`** → 📄 `day00_ex07.sql` (Условная логика `CASE` для категоризации данных)
- 📁 **`src/ex08/`** → 📄 `day00_ex08.sql` (Фильтрация по мат. условиям: остаток от деления)
- 📁 **`src/ex09/`** → 📄 `day00_ex09.sql` (Производные таблицы: подзапрос в части `FROM`)

## ⚙️ Детальное описание выполненных задач

- **Part 1. Базовая фильтрация и сортировка (Tasks 00-01):**  
  Реализовал выборку данных из таблицы `person` с применением множественных условий в `WHERE` (по городу и полу). Настроил алфавитную сортировку результатов для обеспечения предсказуемости вывода.

- **Part 2. Работа с диапазонами (Task 02):**  
  Составил два семантически идентичных, но синтаксически разных запроса для выборки пиццерий по диапазону рейтинга (3.5–5.0). Первый реализован через операторы сравнения (`>=`, `<=`), второй — через ключевое слово `BETWEEN`, что демонстрирует понимание альтернативных подходов к фильтрации.

- **Part 3. Уникальные записи и сложная логика (Task 03):**  
  Написал запрос с использованием `DISTINCT` и логического `OR` для получения уникальных ID посетителей за конкретный период (6–9 января 2022) или посетителей конкретной пиццерии (ID=2). Результат отсортирован по убыванию ID.

- **Part 4. Форматирование и конкатенация строк (Task 04):**  
  Сформировал вычисляемое поле `person_information` с помощью конкатенации, приведя разрозненные данные к единому читаемому формату `Name (age:XX,gender:'X',address:'Y')` с корректным экранированием одинарных кавычек внутри строки.

- **Part 5–6. Скалярные подзапросы без JOIN и IN (Tasks 05-06):**  
  Реализовал выборку имен клиентов, сделавших специфические заказы, строго соблюдая запрет на использование `JOIN` и `IN`. Использовал скалярные подзапросы непосредственно в части `SELECT`. В задании 06 дополнил логику вычисляемым столбцом `check_name`, возвращающим `true`/`false` в зависимости от имени клиента.

- **Part 7. Условная логика (Task 07):**  
  Применил конструкцию `CASE` для категоризации клиентов по возрастным интервалам ('interval #1', '#2', '#3') с последующей сортировкой по созданному вычисляемому полю.

- **Part 8. Математические операции в фильтрации (Task 08):**  
  Отфильтровал таблицу заказов (`person_order`), выбрав только записи с четными идентификаторами с помощью оператора остатка от деления (`id % 2 = 0`).

- **Part 9. Производные таблицы (Task 09):**  
  Построил сложный запрос с использованием подзапроса в части `FROM` для связывания данных о посетителях и пиццериях за заданный период. Реализовал неявное соединение данных, строго соблюдая архитектурное ограничение на запрет явных `JOIN`.

## 🚀 Как проверить

1. **Подготовка:** Убедись, что у тебя развернута СУБД PostgreSQL и применен исходный скрипт `model.sql` из папки `materials` для создания таблиц и тестовых данных.
2. **Запуск:** Перейди в директорию нужного задания (`src/exXX`).
3. **Выполнение:** Запусти файл `day00_exXX.sql` через терминал (`psql -d your_db -f day00_exXX.sql`) или через графический клиент (DataGrip / pgAdmin).
4. **Валидация:** Сверь структуру и порядок строк в выводе с требованиями конкретного задания (особенно внимание к сортировке и именованию вычисляемых столбцов).
